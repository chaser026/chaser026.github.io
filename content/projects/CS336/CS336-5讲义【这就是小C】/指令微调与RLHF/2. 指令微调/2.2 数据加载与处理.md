# 2.2 数据加载与处理

> [!NOTE]
> **本节目标**
> - 理解 Data Packing（数据打包）的核心思想，明确其相较于传统 Padding（填充）的效率优势
> - 掌握在打包流中构造 `input_ids` 与 `labels` 的完整逻辑，包括因果语言模型的标签平移（Shift）实现

---

#### 为什么需要数据打包

在指令微调（SFT）场景中，样本长度通常极不均匀。若采用传统的 Padding 策略，会造成严重的计算浪费。

**Padding 的低效性**： 假设设定 `seq_length=2048`，但平均样本仅约 200 Token，则约 90% 的计算量被消耗在无意义的占位符上，显存带宽利用率极低。

**Packing 的核心思想**： 将整个数据集视为一根连续的 Token 长链，多条"指令-回复"对被拼接在一起，中间仅用 EOS（结束符）分隔。通过这种方式，每一个进入 Transformer Block 的 Token 都是真实语料，计算效率理论上可达 100%。

> [!TIP]
> EOS Token 在 Packing 中承担双重角色：既是序列结束符，也是逻辑隔断——它告诉模型"当前推理结束，下一步开始的是全新的、不相关的指令"。

---

#### Packing 实现的四个核心阶段

以下基于 `InstructionDataset` 类，逐阶段拆解其 Packing 实现逻辑。

##### 阶段一：构造 Token 长链

代码通过循环遍历所有文档，构建两个巨大的线性列表：`all_token_ids` 和 `all_label_ids`。

核心操作：

- `all_token_ids.extend(full_tokens)`：将当前文档的完整 Token 序列追加到长链末尾
- `all_token_ids.append(eos_token_id)`：在每条数据后追加 EOS Token

物理意义：多条数据被物理压扁成一维长链，EOS Token 作为逻辑隔断嵌入其中。

##### 阶段二：精确指令掩码（Precise Instruction Masking）

Packing 过程中必须确保模型只学习"生成回复"的逻辑，而非"背诵问题"。为此采用双轨编码策略：

1. **完整文本编码**：对 `template.format(prompt=p, response=r)` 进行编码，得到 `full_tokens`
2. **仅 Prompt 编码**：对 `template.format(prompt=p, response="")` 进行编码，得到 `prompt_tokens`
3. **标签注入**：在 `all_label_ids` 中，Prompt 对应区间被设为 `-100`（PyTorch CrossEntropyLoss 的忽略索引），Packing 后这些 `-100` 依然保留在长链对应位置，计算 Loss 时自动被忽略

> [!WARNING]
> 代码中对 `prompt_tokens` 执行了 `prompt_tokens = prompt_tokens[:-1]`，目的是防止边界 Token 融合。同时包含安全检查：若 `full_tokens[:len(prompt_tokens)] != prompt_tokens`，则打印警告，提示掩码可能存在轻微偏差。

##### 阶段三：矩阵切片与自回归偏移（Shift Logic）

这是实现因果语言模型"预测下一个词"的关键数学对齐步骤。

**定义块大小**：

$$chunk\_size = seq\_length + 1$$

**变形（Reshape）**： 将一维长链 view 成 `(num_chunks, seq_length + 1)` 的二维矩阵。

**执行 Shift**：

- **Input IDs**：取 `input_chunks[:, :-1]`（索引 $0$ 到 $N-1$）
- **Labels**：取 `label_chunks[:, 1:]`（索引 $1$ 到 $N$）

**结果**： 对于任意位置 $i$ 的输入，其标签精确对应长链中 $i+1$ 位置的 Token。即便 $i$ 跨越了原本的数据边界，由于 EOS 的存在，模型也能学到正确的转折逻辑。

##### 阶段四："死区"过滤（Filtering Invalid Chunks）

Packing 模式下，切片是按固定长度盲目切割的，可能切出全部由 Prompt 组成的数据块。

**识别逻辑**：

$$valid\_chunk\_mask = (final\_labels \neq -100).any(dim=1)$$

**物理含义**： 若一个数据块内所有 Label 均为 `-100`，意味着该 `chunk_size` 长度的片段中没有任何 Response，模型无法产生有效预测反馈。

**处理结果**： 此类"死块"从 `final_input_ids` 中直接剔除，保证每轮迭代都产生有效梯度，避免算力空转。

> [!NOTE]
> 边界条件：若 `num_chunks == 0`（即数据集总 Token 数小于 `chunk_size`），代码会抛出 `ValueError`，提示数据集过小。

#### 完整代码实现

```python
import json
import gzip
import torch
import random
from torch.utils.data import Dataset

class InstructionDataset(Dataset):
    def __init__(self, tokenizer, dataset_path, seq_length: int, shuffle: bool, apply_masking: bool = True):
        self.tokenizer = tokenizer
        # 为了保证 Shift 时有足够的元素，我们实际需要的块长度是 seq_length + 1
        # 但对外暴露的还是 seq_length
        self.seq_length = seq_length 
        self.apply_masking = apply_masking
        
        dataset_path_str = str(dataset_path)
        
        # 1. 加载数据
        docs = []
        open_fn = gzip.open if dataset_path_str.endswith(".gz") else open
        with open_fn(dataset_path_str, "rt", encoding="utf-8") as f:
            for line in f:
                line = line.strip()
                if line:
                    docs.append(json.loads(line))

        # 2. 打乱顺序
        if shuffle:
            random.seed(42)
            random.shuffle(docs)

        # 3. 模版定义 (Alpaca 风格)
        template = (
            "Below is an instruction that describes a task. Write a response that appropriately completes the request.\n\n"
            "### Instruction:\n{prompt}\n\n"
            "### Response:\n{response}"
        )
        
        all_token_ids = []
        all_label_ids = []
        eos_token_id = tokenizer.eos_token_id
        
        print("Tokenizing and applying masks...")
        
        # 4. 双轨编码与精确掩码
        for i, doc in enumerate(docs):
            p = doc.get("prompt", doc.get("instruction", ""))
            r = doc.get("response", doc.get("output", ""))
            
            # 完整文本编码
            formatted_text = template.format(prompt=p, response=r)
            full_tokens = tokenizer.encode(formatted_text, add_special_tokens=False)
            
            # 标签初始化（默认等于 input_ids）
            labels = list(full_tokens)
            
            if self.apply_masking:
                # 仅 Prompt 编码
                prompt_text = template.format(prompt=p, response="")
                prompt_tokens = tokenizer.encode(prompt_text, add_special_tokens=False)
                
                # 防止边界 Token 融合：去掉 Prompt 最后一个 Token 的限制
                prompt_tokens = prompt_tokens[:-1]
                
                # 安全检查：确保前缀完全一致
                if full_tokens[:len(prompt_tokens)] != prompt_tokens:
                    print(f"Warning: Tokenization mismatch at index {i}. Masking might be slightly off.")
                
                # 执行掩码：将 Prompt 部分的标签设为 -100
                mask_len = len(prompt_tokens)
                labels[:mask_len] = [-100] * mask_len
            
            # 将当前文档追加到长链，并在末尾添加 EOS
            all_token_ids.extend(full_tokens)
            all_token_ids.append(eos_token_id)
            
            all_label_ids.extend(labels)
            # EOS 是模型必须学习输出的，所以标签处保留其真实 ID，不能设为 -100
            all_label_ids.append(eos_token_id)
            
        # 转换为 Tensor 以便进行高效操作
        all_token_ids = torch.tensor(all_token_ids, dtype=torch.long)
        all_label_ids = torch.tensor(all_label_ids, dtype=torch.long)

        # 5. 执行 Packing 与 Shift 逻辑
        print("Packing sequences into fixed chunks...")
        
        # 为了能平移一位（Shift），我们需要切出一个长为 seq_length + 1 的块
        chunk_size = self.seq_length + 1 
        num_chunks = len(all_token_ids) // chunk_size
        
        if num_chunks == 0:
            raise ValueError(f"Dataset is too small! Total tokens ({len(all_token_ids)}) < required chunk size ({chunk_size})")

        # 截断多余的部分并变形
        input_chunks = all_token_ids[:num_chunks * chunk_size].view(num_chunks, chunk_size)
        label_chunks = all_label_ids[:num_chunks * chunk_size].view(num_chunks, chunk_size)

        # 6. 执行 Shift 逻辑：产生最终的输入和标签
        # 输入：取前 seq_length 个 [0 : N-1]
        self.final_input_ids = input_chunks[:, :-1]
        # 标签：取后 seq_length 个 [1 : N]
        self.final_labels = label_chunks[:, 1:]

        # 7. "死区"剔除 (Filtering Invalid Chunks)
        # 检查每个序列的 Labels：如果一整行全都是 -100，说明这 chunk_size 个 token 全是 Prompt
        # 这种数据无法产生梯度，必须丢弃。
        valid_chunk_mask = (self.final_labels != -100).any(dim=1)
        
        total_dropped = num_chunks - valid_chunk_mask.sum().item()
        if total_dropped > 0:
            print(f"Dropped {total_dropped} / {num_chunks} chunks ({total_dropped/num_chunks:.1%}) that contained ONLY masked prompt tokens.")
        else:
            print("All chunks are valid.")

        # 保留有效的数据块
        self.final_input_ids = self.final_input_ids[valid_chunk_mask]
        self.final_labels = self.final_labels[valid_chunk_mask]

    def __len__(self):
        return len(self.final_input_ids)

    def __getitem__(self, i):
        return {
            "input_ids": self.final_input_ids[i].clone(),
            "labels": self.final_labels[i].clone()
        }
```

#### 实验与性能对比

| 指标 | Padding 模式 | Packing 模式（当前代码） |
| --- | --- | --- |
| Token 利用率 | 取决于样本平均长度（通常 <30%） | ~100% |
| Attention Mask | 需要复杂的二维掩码处理 Padding | 无需 Padding 掩码，计算逻辑简化 |
| 收敛速度 | 较慢，有效梯度更新频率低 | 极快，每个 Batch 包含更多有效信息 |
| 模型表现 | 稳定 | 稳定（前提是 EOS 处理正确且剔除了死块） |

> [!IMPORTANT]
> Packing 模式下模型表现稳定的前提条件：
> - EOS Token 在标签中保留真实 ID（而非设为 `-100`），确保模型学会在指令结束后生成回复
> - "死块"已被正确剔除，避免无效梯度更新干扰训练\n
