## 模型分类：通用助手与推理模型

在模型对齐（Alignment）的语境下，大规模语言模型沿两种不同方向演进。理解二者的差异是后续学习的基础。

### 通用助手（Generalist Assistant）

通用助手旨在模拟人类对话、遵循复杂指令并处理多样化的自然语言任务。其开发路径为：

1. 从仅具备续写能力的基座模型（Base Model）出发
2. 通过监督微调（SFT）转变为对话助手
3. 再通过偏好对齐（如 DPO）使其符合人类价值观

**核心特征**：

- **指令遵循**：准确识别并执行用户意图（如摘要、翻译、角色扮演）
- **人格属性**：遵循"有用、诚实、无害（HHH）"原则，具备特定的语气风格
- **直觉响应**：侧重语言的流畅性与语义连贯，通常进行快速、直接的输出

### 推理模型（Reasoning Model）

推理模型专注于解决逻辑复杂、涉及多步规划或严密推导的任务（如 DeepSeek-R1）。

**核心特征**：

- **慢思考**：引入思维链（Chain of Thought, CoT），在输出最终答案前进行显式的逻辑推导
- **强化学习驱动**：核心能力通常源于大规模强化学习，通过"自我博弈"与奖励机制优化推理路径

> [!TIP]
> **常见误区**：通用助手并非"不会推理"，推理模型也并非"不能对话"。二者的区别在于训练目标与默认行为模式的侧重不同，而非能力的绝对有无。

## 消息架构：交互的三位一体

在主流对话框架中，输入模型的信息流由三种核心角色（Role）组成。分词结果可通过可视化网站查看：https://tiktokenizer.vercel.app/

| 角色 | 名称 | 作用 |
|------|------|------|
| System | System Prompt（系统消息） | 设定模型的身份、任务范围、语言风格及必须遵守的安全约束 |
| User | User Prompt（用户消息） | 代表用户的直接指令或提问，是交互的触发起点 |
| Assistant | Assistant Prompt（助手消息） | 代表模型生成的回复；在多轮对话中充当"上下文记忆" |

## 角色机制在 SFT 阶段的实现

在监督微调（SFT）阶段，模型不仅学习如何回答问题，还学习如何识别上述三种角色。这通过格式化数据集和特定的训练损失计算来实现。

### 训练数据的结构化拼接

构建 SFT 数据集时，对话记录被转换为带有特殊控制标记（Special Tokens）的文本序列。以常见的 ChatML 格式为例：

```text
<system>
你是一个人工智能助手，请用严谨的语言回答问题。
</system>
<user>
请解释什么是量子纠缠。
</user>
<assistant>
量子纠缠是量子力学中的一种现象...
</assistant>
```

其中：

- `<system>` 和 `</system>`、`<user>` 和 `</user>`、`<assistant>` 和 `</assistant>` 用于界定消息边界
- `system`、`user`、`assistant` 标签明确指代当前片段的角色身份

> [!NOTE]
> 经过大量此类格式数据的训练，模型能够识别出：`<system>` 标记后的指令具有全局最高优先级，而 `<assistant>` 标记后则应开始执行生成任务。

### 训练损失的选择性计算

在 SFT 训练中，虽然整个序列都被输入模型，但损失函数通常**只针对 Assistant 部分的 Token** 进行计算。

**逻辑**： 模型需要学习的是"给定 System 指令和 User 提问，如何生成 Assistant 回复"。我们不需要模型去学习如何预测 System Prompt 或 User Prompt（因为那是输入端），而是强制模型通过反向传播来拟合 Assistant 的输出路径。

### System Prompt 的构建策略

在 SFT 数据集中，System Prompt 并非固定不变。为增强模型的鲁棒性，开发者通常采用以下策略：

| 策略类型 | 示例 | 用途 |
|-----------|------|------|
| 通用型 | "你是一个由某公司开发的 AI 助手" | 占据数据集大部分，确立基础人格设定 |
| 任务特定型 | "你是一个专业的代码审查器"、"你是一个翻译官" | 引入多样化系统指令，使模型学会根据不同设定调整输出模态 |
| 空或默认型 | 模拟用户未设置系统消息的情况 | 确保模型在缺乏外部约束时仍能正常运作 |

## 系统提示词的安全性与可控性意义

### 物理位置与注意力权重

在输入序列中，System Prompt 处于起始位置。根据 Transformer 架构的注意力机制特性，序列首部信息对后续生成的引导作用至关重要，有助于模型在长对话中维持身份。

### 权限隔离与防御注入

**防御提示词注入（Prompt Injection）**： 恶意用户可能在 User Prompt 中输入"忽略之前所有指令"。通过在训练阶段强化 System 域的优先级，模型可以学会区分"开发者的底线指令"与"用户的临时指令"，从而降低被误导的风险。

**开发者意图隐藏**： System Prompt 作为"保险箱"，允许开发者预设安全红线（如严禁提供危险建议）。这种角色分离机制有效防止了模型在复杂交互中偏离合规轨道。

> [!WARNING]
> **注意事项**：System Prompt 的安全性并非绝对保障。在实际部署中，仍需结合输入过滤、输出审核等多层防御手段，不能仅依赖 System Prompt 一道防线。
