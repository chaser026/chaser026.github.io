# 6.5 On-policy vs Off-policy

> [!NOTE]
> **本节目标**
> - 理解 on-policy 与 off-policy 训练在 GRPO 框架下的区别与联系
> - 掌握 epoch 数、batch size 等超参数对训练稳定性和最终性能的影响
> - 通过 Math12K 与 GSM8K 实验数据，分析大 batch 条件下重复利用数据的风险与应对策略

---

## 实验配置

### 固定超参数

以下为本节实验中保持不变的超参数设置：

| 参数 | 值 | 说明 |
|---|---|---|
| `train_batch_size` | 64 / 128 / 256 | 训练批次大小（Anchor_Batch = 256） |
| `epochs_per_rollout_batch`（epoch / E） | 1 / 2 / 3 | 每轮 rollout 数据的训练轮数 |
| `Anchor_LR` | 3e-5 | 锚点学习率 |
| 实际学习率 `LR` | `Anchor_LR * (train_batch_size / Anchor_Batch) / sqrt(epoch)` | 随 batch size 与 epoch 动态调整 |
| `gradient_accumulation_steps` | `train_batch_size / MicroBS` | 梯度累积步数 |
| `MicroBS` | 8 | 微批次大小 |
| `group_size` | 8 | 每组样本数 |
| `length_norm_type` | `mask_normalize` | 长度归一化方式 |
| `loss_type` | `grpo_clip` | 损失函数类型 |
| `rollout_batch_size` | 256 | 每次 rollout 生成的样本数 |

> [!TIP]
> **学习率缩放公式**
> $$
> LR = \text{Anchor\_LR} \times \frac{\text{train\_batch\_size}}{\text{Anchor\_Batch}} \times \frac{1}{\sqrt{\text{epoch}}}
> $$
> 该公式确保在不同 batch size 和 epoch 下，有效更新步长保持合理范围。

### 不同 batch size 下的训练表现

#### batch_size = 64

- 随着 epoch 从 1 增加到 3，模型性能呈现**单调提升**趋势
- 说明在小 batch 条件下，增加 epoch 有助于提升样本利用率，加快性能增长
- 但整体收敛速度较慢，且最终性能受限

#### batch_size = 128

- 模型在较少 step（约 100 步左右）内即可达到性能上限
- epoch 从 1 增加至 2 带来**明显收益**
- 继续增加至 3 提升有限，表明 2 个 epoch 已足以充分利用该规模的数据

#### batch_size = 256

- epoch 增加反而导致性能**快速下降**
- 仅单 epoch（E=1）训练最为稳定
- 表明在大 batch 条件下，多次重复利用同一批数据可能导致过拟合或策略分布漂移，从而引发性能退化

> [!WARNING]
> **关键结论**
> 在大 batch 条件下增加 epoch 数更易引发训练不稳定。其主要原因在于：
> 1. 大 batch 降低了梯度估计的随机性，使多次更新沿相似方向累积，**放大策略分布偏移**；
> 2. 过度重复利用同一批数据会加剧**分布失配**与**重要性权重偏移**，进而导致性能退化。
>
> 因此，大 batch 设置下应适当减少 epoch 以控制更新幅度。
