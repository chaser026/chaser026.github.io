# 2.2 提示词与回答的张量化

> [!NOTE]
> **本节目标**
> - 掌握序列拼接策略：学习如何正确组合 Prompt 与 Response
> - 深刻理解偏移（Shift）逻辑：理清因果语言模型（Causal LM）中输入与标签的对应关系
> - 实现标签掩码（Label Masking）：掌握 `response_mask` 的核心原理，确保模型只为"回答"负责
> - 处理 Batch 填充（Padding）：学习如何将变长序列对齐为统一形状的张量
> - 区分三种掩码：因果掩码（Causal Mask）、填充掩码（Padding Mask）和损失掩码（Loss Mask / Label Mask）

---

## 核心原理：从文本到训练张量

本节的核心任务是构建符合因果语言模型（Causal LM）训练规范的输入张量。这不仅涉及分词（Tokenization），更涉及对模型学习目标的精确定义——即明确"模型应当为哪些位置的预测错误负责"。

### 序列拼接与终止符

SFT 的原始数据通常由"提示词（Prompt）"和"专家回答（Response）"两部分组成。在张量化过程中，我们将二者拼接为单一序列。

- **终止符（EOS Token）的必要性**：在 Response 末尾必须显式添加结束标记（如 `<|endoftext|>`）
- **训练目标**：模型不仅要学习生成推理过程，更要学习识别逻辑终点。若缺少终止符，模型在实际推理时将无法主动停止，导致输出冗余或陷入死循环

> [!WARNING]
> 终止符是 SFT 数据预处理中不可省略的步骤。缺少 EOS 会直接导致推理阶段的生成失控。

### 自回归偏移与张量对齐

因果语言模型遵循自回归原理，即基于历史 Token 序列预测当前 Token。在数学表达上，模型学习的是条件概率：

$$P(x_t \mid x_1, x_2, \dots, x_{t-1})$$

为了在一次前向传播中计算整个序列的 Loss，我们需要构造两组长度为 $N-1$ 的张量（设原始拼接序列长度为 $N$）：

| 张量 | 取值范围 | 说明 |
|------|----------|------|
| `input_ids` | $[0, N-1)$，即前 $N-1$ 个 Token | 最后一个 Token 被剔除，因为它没有后续目标可供预测 |
| `labels` | $[1, N]$，即后 $N-1$ 个 Token | 第一个 Token 被剔除，因为它作为初始输入，不属于被预测的目标 |

**偏移本质**：这种错位确保了输入张量的第 $i$ 个元素，其对应的监督标签正好是序列中的第 $i+1$ 个元素，从而完美契合"预测下一个词"的训练目标。

### 标签掩码与梯度分配

尽管拼接后的序列是一个整体，但并非所有位置的预测错误都应当反馈给模型。

**掩码理由**：Prompt 部分是由人类或外部系统提供的背景信息。如果对 Prompt 部分计算交叉熵损失（Loss），模型将分配参数容量去尝试"背诵"问题，导致两个严重后果：

- **参数浪费**：模型应当专注于学习推理逻辑，而非记忆固定的提问方式
- **幻觉加剧**：模型可能学会过度拟合特定的提问语气，从而在面对变体提问时泛化性不足，产生无关输出

**技术方案（Response Mask）**：引入一个与 `labels` 形状一致的布尔型张量（Mask），将 Prompt 部分对应的权重设为 0（或在 Loss 函数中设置 `ignore_index=-100`）。

**执行效果**：在计算平均损失时，只有 Response 部分的预测准确性会产生有效梯度。这确保了模型仅针对"如何回答问题"进行参数优化，划清了输入背景与学习目标之间的责任界限。

> [!TIP]
> `response_mask`、因果掩码（Causal Mask）和填充掩码（Padding Mask）是三种不同用途的掩码，不可混淆：
> - **因果掩码**：防止模型在训练时"偷看"未来 Token（由模型结构内部处理）
> - **填充掩码**：标识 Padding 位置，避免其参与注意力计算
> - **损失掩码（Label Mask）**：即 `response_mask`，控制哪些位置的 Loss 参与梯度回传

## 代码实现

以下函数完成从原始文本到训练张量的完整流程：分词 → 拼接 → 构造掩码 → 填充对齐 → 偏移切割。

```python
def tokenize_prompt_and_output(
    prompt_strs: List[str], 
    output_strs: List[str], 
    tokenizer: PreTrainedTokenizer
) -> Dict[str, torch.Tensor]:
    """
    对 prompt 和 response 进行分词，拼接，并生成对应的 response_mask。
    """
    all_input_ids = []
    all_response_masks = []
    all_lengths = []

    # 1. 编码与拼接
    for p_str, o_str in zip(prompt_strs, output_strs):
        # add_special_tokens=False 是因为我们要手动控制 BOS/EOS 的添加
        p_ids = tokenizer.encode(p_str, add_special_tokens=False)
        o_ids = tokenizer.encode(o_str, add_special_tokens=False)
        
        combined_ids = p_ids + o_ids
        all_input_ids.append(combined_ids)
        all_lengths.append(len(combined_ids))
        
        # 构造初始 mask：Prompt 部分填 0，Response 部分填 1
        mask = [0] * len(p_ids) + [1] * len(o_ids)
        all_response_masks.append(mask)

    # 2. 确定 Batch 最大长度用于对齐 (Padding)
    max_len = max(all_lengths)
    batch_size = len(prompt_strs)
    # 优先寻找 pad_token，如果没有（如早期 Llama），则借用 eos_token
    pad_id = tokenizer.pad_token_id if tokenizer.pad_token_id is not None else tokenizer.eos_token_id

    # 3. 填充 (Padding) 逻辑
    padded_input_ids = torch.full((batch_size, max_len), pad_id, dtype=torch.long)
    padded_masks = torch.zeros((batch_size, max_len), dtype=torch.long)

    for i, (ids, m) in enumerate(zip(all_input_ids, all_response_masks)):
        length = len(ids)
        # 训练时通常使用右填充 (Right Padding)
        padded_input_ids[i, :length] = torch.tensor(ids)
        padded_masks[i, :length] = torch.tensor(m)

    # 4. 执行核心 Shift 操作
    # 假设原始序列长度为 N
    # input_ids: 取 [0, N-1]，作为预测的上下文
    final_input_ids = padded_input_ids[:, :-1]
    
    # labels: 取 [1, N]，作为预测的目标
    # .clone() 确保在内存中独立，防止梯度计算异常
    final_labels = padded_input_ids[:, 1:].clone()
    
    # response_mask: 必须对应 labels 的位置，所以也取 [1, N]
    final_response_mask = padded_masks[:, 1:]

    return {
        "input_ids": final_input_ids,
        "labels": final_labels,
        "response_mask": final_response_mask
    }
```

### 实现要点说明

- **`add_special_tokens=False`**：手动控制 BOS/EOS 的添加时机，避免分词器自动插入干扰拼接逻辑
- **右填充（Right Padding）**：训练时将有效内容靠左对齐，右侧用 `pad_id` 填充，这是因果 LM 的标准做法
- **`pad_id` 回退策略**：优先使用 `tokenizer.pad_token_id`，若不存在（如早期 Llama 系列）则回退到 `tokenizer.eos_token_id`
- **`.clone()` 的必要性**：`final_labels` 必须是独立的内存副本，否则后续 in-place 操作可能引发梯度计算异常
- **`response_mask` 的偏移**：由于 `labels` 和 `input_ids` 都做了左移一位的切割，`response_mask` 也必须同步取 `[:, 1:]`，以保持与 `labels` 的位置对齐
