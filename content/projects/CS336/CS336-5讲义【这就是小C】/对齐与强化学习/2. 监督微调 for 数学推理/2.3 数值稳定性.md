# 2.3 数值稳定性

> [!NOTE]
> **本节目标**
> - 理解熵（Entropy）的数学与物理意义，掌握其在大模型预测中作为不确定性度量的作用
> - 利用 Log-Sum-Exp (LSE) 技巧重新推导熵公式，规避数值崩溃
> - 明确训练过程中需要记录哪些维度的熵，以及如何解读熵的曲线图

#### 核心概念：预测熵（Next-token Entropy）

##### 熵的定义与直觉

在信息论中，熵 $H(p)$ 衡量概率分布 $p$ 的不确定性。对于大语言模型，在预测下一个 token 时：

- **高熵（High Entropy）**：模型认为多个候选词出现的概率非常接近，通常发生在句子开头或语义模糊的位置
- **低熵（Low Entropy）**：模型高度确信某一个特定词将出现

熵的标准定义为：

$$H(p) = -\sum_{i} p_i \log p_i$$

其中 $p_i$ 是第 $i$ 个 token 的预测概率。

##### 熵在对齐（Alignment）中的关键作用

在后续 GRPO 或 PPO 强化学习阶段，模型为追求更高奖励（Reward）容易"走捷径"，引发两类严重问题：

1. **模式坍缩（Mode Collapse）**：训练不当时，模型发现几句固定的高分套话即可稳拿奖励，导致预测分布极度集中，熵骤降至接近 0
2. **训练崩溃**：分布过于集中时梯度异常尖锐，极易引发数值溢出

> [!WARNING]
> 监控熵的变化是判断 RL 训练是否健康的**第一标准**。一旦熵曲线出现异常暴跌，必须立即排查训练配置。

---

#### 数值稳定性：Log-Sum-Exp (LSE) 技巧

##### Softmax 的天生缺陷

Softmax 的计算公式为：

$$\text{softmax}(z_i) = \frac{e^{z_i}}{\sum_j e^{z_j}}$$

在 FP16/BF16 精度下，一旦 $z_i$ 超过约 11.0，$e^{z_i}$ 就会迅速溢出，导致后续计算产生 NaN。

##### 熵公式的稳定化重构

**原始公式**（直接代入 $p_i = \text{softmax}(z_i)$）：

$$H = -\sum_i p_i \log p_i$$

**推导过程**：

将 $p_i = \frac{e^{z_i}}{\sum_j e^{z_j}}$ 代入并利用对数运算性质：

$$\log p_i = z_i - \log\sum_j e^{z_j}$$

带回熵公式：

$$H = -\sum_i p_i (z_i - \log\sum_j e^{z_j}) = -\sum_i p_i z_i + \log\sum_j e^{z_j}$$

由于 $\sum_i p_i = 1$，最终得到**稳定版公式**：

$$H = \underbrace{\log\sum_j e^{z_j}}_{\text{LSE}(z)} - \underbrace{\sum_i p_i z_i}_{E[z]}$$

> [!NOTE]
> **优势**：该公式避免了对极小概率值 $p_i$ 直接取对数（$p_i \to 0$ 时 $\log p_i \to -\infty$ 导致 NaN），全程只涉及 Log-Sum-Exp 和乘法加权，数值稳定。

#### 需要记录的熵指标

训练中需监控两类熵，它们的计算范围、含义和曲线特征各不相同。

##### avg_global_entropy（全局有效熵）

- **计算范围**：Prompt + Response（序列中所有非 Padding 的 Token）
- **含义**：模型对整条序列预测的平均不确定性
- **监控价值**：
  - **预训练记忆检测**：Prompt 部分虽不参与 Loss 计算，但前向传播时模型仍会预测其中的词。若 Global Entropy 极低，说明模型对这些指令或问题非常熟悉
  - **分布平滑度**：反映模型处理输入到输出全过程的平均"清醒程度"

##### avg_res_entropy（响应内容熵）—— 核心指标

- **计算范围**：仅限 Response 部分（思考过程和最终答案）
- **含义**：模型在执行生成任务时的平均不确定性
- **监控价值**：
  - **对齐质量监控**：SFT 或 RL 训练最直接的反馈，期望看到"从迷茫到坚定"的变化过程
  - **防止模式坍缩（重点）**：若该值突然暴跌至接近 0，意味着模型学会了"偷懒"，反复输出固定的、概率被拉到 100% 的无意义套话

> [!WARNING]
> `avg_res_entropy` 是捕捉模型"学坏了"的最佳哨兵指标，训练中应设置阈值告警。

##### 两类指标的对比

| 维度 | avg_global_entropy（全局） | avg_res_entropy（响应） |
|---|---|---|
| 覆盖内容 | 题目 + 思考 + 答案 | 思考 + 答案 |
| 波动性 | 较低（受固定题目干扰） | 较高（反映真实生成逻辑） |
| 训练初期的值 | 通常较低（题目内容通常很确定） | 通常很高（模型不知道怎么解题） |
| 理想趋势 | 平缓下降 | 平滑下降并维持在健康水平 |
| 若该值降为 0 | 模型可能背过了这道题 | 模型发生模式坍缩，只会说复读机式的话 |

#### 代码实现与知识点解析

##### compute_entropy：数值稳定的熵计算

```python
def compute_entropy(logits: torch.Tensor) -> torch.Tensor:
    """
    计算每个位置预测分布的熵。
    """
    # 1. 计算 LSE 部分 (分母的对数)
    # torch.logsumexp 内部使用了 (z - z_max) 的技巧来防止 exp 溢出
    lse = torch.logsumexp(logits, dim=-1) # 形状: (B, L)
    
    # 2. 计算概率 p
    probs = F.softmax(logits, dim=-1) # 形状: (B, L, Vocab)
    
    # 3. 计算加权期望 E[z] = sum(p_i * z_i)
    # 这一步体现了稳定化公式的第二项
    exp_logits = torch.sum(probs * logits, dim=-1) # 形状: (B, L)
    
    # 4. H = LSE - E[z]
    entropy = lse - exp_logits
    return entropy
```

##### get_response_log_probs：稳健的概率提取

```python
def get_response_log_probs(
    model: PreTrainedModel,
    input_ids: torch.Tensor,
    labels: torch.Tensor,
    return_token_entropy: bool = False,
) -> Dict[str, torch.Tensor]:
    """
    获取模型对指定 labels 的条件对数概率 log p(y|x)。
    """
    # 前向传播
    outputs = model(input_ids)
    logits = outputs.logits

    # 核心：直接使用 F.log_softmax 而不是 log(softmax(...))
    # log_softmax 在算子层面合并了计算，具有更好的数值精度
    log_probs_all = F.log_softmax(logits, dim=-1)

    # 提取目标 ID 的概率：使用 gather 从 Vocab 维度精准定位
    # labels index 需要 unsqueeze 补齐维度以匹配 (B, L, Vocab)
    log_probs = torch.gather(
        log_probs_all, 
        dim=-1, 
        index=labels.unsqueeze(-1)
    ).squeeze(-1) 

    results = {"log_probs": log_probs}

    if return_token_entropy:
        # 将熵作为元数据返回，用于 WandB 监控
        results["token_entropy"] = compute_entropy(logits)

    return results
```

> [!NOTE]
> **实现要点**：`F.log_softmax` 在算子层面合并了 log 与 softmax 的计算，比先算 softmax 再取对数具有更好的数值精度，是提取对数概率的推荐做法。
