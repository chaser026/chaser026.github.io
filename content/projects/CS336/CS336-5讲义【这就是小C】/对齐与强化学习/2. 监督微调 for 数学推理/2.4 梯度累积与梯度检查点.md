# 2.4 梯度累积与梯度检查点

> [!NOTE]
> **本节目标**
> - 理清 Batch 与 Micro-batch 的逻辑关系，掌握梯度累积的核心计算公式
> - 理解梯度检查点机制，明白如何用"时间"换取"显存空间"

---

#### 前置知识：反向传播与链式求导

梯度累积与梯度检查点均建立在反向传播（Backpropagation）和链式求导（Chain Rule）的基础之上。反向传播通过链式法则逐层计算损失对各参数的梯度，而梯度检查点正是针对这一过程中中间激活值的存储策略进行优化。

---

## 一、梯度累积（Gradient Accumulation）

### 核心矛盾：逻辑 Batch Size vs 物理显存

训练大语言模型（LLM）时，通常需要较大的 Batch Size（如 128 或 256）来保证梯度更新的平滑性与训练收敛性。然而实际情况是，单张显卡的显存往往连 Batch Size 为 4 的模型都无法容纳。

> [!TIP]
> **关键区分**：逻辑 Batch Size 决定模型更新的统计质量，物理 Micro-batch Size 受限于硬件显存，二者通过梯度累积桥接。

### 核心概念与公式

| 术语 | 符号 | 含义 | 示例 |
|------|------|------|------|
| Micro-batch Size | $m$ | 硬件实际每轮前向传播处理的数据量 | $m = 2$ |
| Accumulation Steps | $N$ | 梯度累积的步数 | $N = 128 / 2 = 64$ |
| Logical Batch Size | $B$ | 模型更新一次权重时实际参考的数据量 | $B = 128$ |

三者满足核心公式：

$$B = m \times N$$

### 执行逻辑

1. **分批前向传播**：每次只喂入 $m$ 个样本。
2. **损失缩放**：由于梯度是多批次求和得到的，需将 Loss 除以 $N$ 进行均值化，使 `optimizer.step()` 等效于计算逻辑 Batch 的平均梯度。
3. **计算梯度**：调用 `loss.backward()`，梯度累加在模型参数的 `.grad` 属性中，而非覆盖。
4. **按需更新**：重复上述过程 $N$ 次后，才调用一次 `optimizer.step()` 更新参数，随后清空梯度。

> [!WARNING]
> **常见误区**：若忘记对 Loss 做除以 $N$ 的缩放，等效学习率将被放大 $N$ 倍，导致训练不稳定甚至发散。

---

## 二、梯度检查点（Gradient Checkpointing）

### 核心矛盾：激活值的显存吞噬

大模型训练中显存占用主要由两部分构成：

| 组成部分 | 特点 | 示例 |
|----------|------|------|
| 模型参数 | 固定大小，与输入无关 | 7B 模型 BF16 约 14 GB |
| 激活值（Activations） | 随序列长度 $L$ 和 Batch Size $B$ 线性增长 | 长序列时可达数十 GB |

默认情况下，PyTorch 会在前向传播中保存每一层的输出（激活值），以便反向传播时计算梯度。这在长序列场景下会迅速耗尽显存。

### 解决方案：不保存，用时再算

梯度检查点采取"决绝"策略：

- **前向传播**：不保存中间层激活值，仅保留少数几个"检查点"（checkpoint）。
- **反向传播**：当需要某一层的激活值时，从最近的检查点出发，临时重新执行一遍前向计算得出该值。

> [!TIP]
> **收益与代价**：显存占用大幅下降，尤其在处理长序列（如数学推理中的长 CoT）时效果立竿见影；代价是计算时间增加约 30%，因为部分前向传播被执行了两次。

---

## 三、代码实现

以下代码基于 Transformers 库的 SFT（Supervised Fine-Tuning）训练场景，展示两项技术的简洁实现。

```python
# --- 1. 梯度检查点 (Gradient Checkpointing) ---
# 只需一行代码，大幅降低长序列训练时的显存压力
model.gradient_checkpointing_enable()

# --- 2. 梯度累积 (Gradient Accumulation) ---
# 假设逻辑 batch 为 32，物理 batch 只能跑 2
logical_batch_size = 32
micro_batch_size = 2
accum_steps = logical_batch_size // micro_batch_size

optimizer.zero_grad()

for i, batch in enumerate(dataloader):
    # 前向传播
    outputs = model(input_ids=batch["input_ids"], labels=batch["labels"])
    
    # 核心：将 Loss 缩放。因为最后累积的梯度是多批次的和，
    # 缩放后 optimizer.step() 相当于计算了 logical batch 的平均梯度。
    loss = outputs.loss / accum_steps
    
    # 反向传播，累积梯度
    loss.backward()
    
    # 达到累积步数，执行更新
    if (i + 1) % accum_steps == 0:
        torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)  # 梯度裁剪防止震荡
        optimizer.step()
        optimizer.zero_grad()
```

> [!NOTE]
> **实现细节**：
> - `model.gradient_checkpointing_enable()` 是 Transformers 模型的内置方法，内部会自动对支持的层启用检查点机制。
> - 梯度裁剪 `clip_grad_norm_` 在每次参数更新前执行，阈值设为 1.0，用于防止梯度爆炸。
> - `optimizer.zero_grad()` 在循环开始前和每次更新后各调用一次，确保梯度不会跨逻辑 Batch 污染。
