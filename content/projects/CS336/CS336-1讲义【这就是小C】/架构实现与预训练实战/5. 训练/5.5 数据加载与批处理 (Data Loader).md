# 5.5 数据加载与批处理 (Data Loader)

> **本节目标**

> - 理解并运用内存映射技术 `np.memmap` 进行大规模数据集的内存优化

## 训练任务的本质：下一个 Token 预测

语言模型的核心训练目标是：**给定前 $t$ 个词，预测第 $t+1$ 个词**。

为了提升训练效率，我们在一个长度为 $\text{max\_seq\_length}$ 的滑动窗口内，让模型在**每一个位置**都预测它的下一个词，而非仅预测最后一个词。

### 输入与目标的构造

设窗口长度为 $\text{max\_seq\_length}$，起始索引为 $i$：

- **输入 $x$**：从索引 $i$ 开始、长度为 $\text{max\_seq\_length}$ 的序列

$$x = (x_i,\ x_{i+1},\ \dots,\ x_{i+\text{max\_seq\_length}-1})$$

- **目标 $y$**：输入序列整体向后平移一位，长度同样为 $\text{max\_seq\_length}$

$$y = (x_{i+1},\ x_{i+2},\ \dots,\ x_{i+\text{max\_seq\_length}})$$

> [!TIP]
> **物理意义**：当模型看到输入中的第一个词 $x_i$ 时，它应当输出 $x_{i+1}$；看到 $x_{i+1}$ 时，应输出 $x_{i+2}$，依此类推。这种偏移设计允许我们在**一次前向计算**中完成 $\text{max\_seq\_length}$ 次学习信号的传递。

---

## 代码实现逻辑拆解

由于数据集通常极大（数百 GB 级别），无法使用传统 Python `list` 存储。实际实现基于 **Numpy 数组**（通常配合内存映射 `mmap`）进行操作。

整个批处理流程分为以下四步：

### 1. 确定合法边界

首先计算数据集中最后一个合法的起始索引：

```python
max_idx = n - max_seq_length - 1
```

> [!WARNING]
> **为什么要减 1？** 因为目标序列 $y$ 需要取到 $x_{i+\text{max\_seq\_length}}$ 的位置。如果不减 1，当随机采样到序列末尾时，切片操作会发生**越界错误**。

### 2. 随机采样起始点

```python
ix = torch.randint(0, max_idx + 1, (batch_size,))
```

一次性生成 `batch_size` 个随机整数，作为本批次中每条样本的起始索引。这种随机性保证模型每一轮（epoch）看到的文本组合都不同，有利于**泛化能力**的提升。

### 3. 内存切片与堆叠

```python
x_stack = [dataset[i : i + max_seq_length] for i in ix]
y_stack = [dataset[i + 1 : i + max_seq_length + 1] for i in ix]
```

利用列表推导式从 Numpy 数组中提取片段。此时数据仍驻留在 **CPU 内存**中，尚未转移到 GPU。

### 4. 张量化与类型转换

```python
x = torch.from_numpy(np.array(x_stack)).to(device).long()
```

> [!IMPORTANT]
> **类型转换是关键步骤**：原始数据通常为 `uint16` 或 `int32`，但 PyTorch 的 `Embedding` 层要求输入必须是 `int64`（即 `Long` 类型）。因此必须显式调用 `.long()`，否则会在训练时抛出类型不匹配错误。

## 内存优化：内存映射 (np.memmap)

这是大模型训练的**标配技术**，尤其适用于数据集远超物理内存的场景。

### 基本用法

在训练脚本中，不使用 `f.read()` 一次性读取整个文件，而是：

```python
# 训练脚本中的典型用法
data = np.memmap('train.bin', dtype=np.uint16, mode='r')
```

### 工作原理

| 特性 | 说明 |
|------|------|
| 映射方式 | 在磁盘文件与逻辑内存地址空间之间建立映射，**不真正将数据读入 RAM** |
| 按需加载 | 当执行切片操作（如 `dataset[i:i+L]`）时，操作系统才从磁盘精确读取所需的几 KB 数据到缓存 |
| 核心价值 | 可在 16 GB 内存的个人电脑上，训练存储在 500 GB 硬盘中的数据集 |

> [!TIP]
> `np.memmap` 与本节的 `get_batch` 函数天然配合：`get_batch` 每次只切片一小段数据，操作系统按需从磁盘调入，内存占用始终可控。

---

## 完整代码实现

以下是整合上述所有步骤的完整 `get_batch` 函数：

```python
import torch
import numpy as np
import numpy.typing as npt

def get_batch(
    dataset: npt.NDArray, 
    batch_size: int, 
    max_seq_length: int, 
    device: str
) -> tuple[torch.Tensor, torch.Tensor]:
    """
    随机采样一个训练批次。
    
    返回:
        x: 输入张量，形状 [batch_size, max_seq_length]
        y: 目标张量，形状 [batch_size, max_seq_length]
    """
    n = len(dataset)
    # 最后一个可用的起点，必须留出 max_seq_length 的空间给 x，再多留 1 位给 y
    max_idx = n - max_seq_length - 1
    
    # 随机选择 batch_size 个起始点
    ix = torch.randint(0, max_idx + 1, (batch_size,))
    
    # 提取序列并转为 Numpy 数组，再转为 Tensor
    # 这样做比循环里逐个 to(device) 快得多
    x = torch.stack([torch.from_numpy(dataset[i : i + max_seq_length].astype(np.int64)) for i in ix])
    y = torch.stack([torch.from_numpy(dataset[i+1 : i + max_seq_length + 1].astype(np.int64)) for i in ix])
    
    # 一次性搬运到 GPU
    return x.to(device), y.to(device)
```

> [!NOTE]
> **性能提示**：代码中先在 CPU 上完成 `torch.stack` 拼接，最后一次性调用 `.to(device)` 将整个批次搬运到 GPU。这比在循环内逐条调用 `.to(device)` 效率高得多，因为减少了 GPU 通信开销。
