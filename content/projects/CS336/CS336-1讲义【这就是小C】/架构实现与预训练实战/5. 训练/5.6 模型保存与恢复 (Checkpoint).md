# 5.6 模型保存与恢复 (Checkpoint)

> [!NOTE]
> **本节目标**
> - 理解恢复模型训练（从断点继续训练）需要用到哪些信息
> - 掌握需要保存的信息及其作用
> - 认识优化器状态和学习率调度器丢失带来的数值后果

---

## 为什么需要 Checkpoint

训练深度学习模型往往耗时数小时甚至数天，中途意外中断（如机器故障、进程被杀、OOM 等）在所难免。Checkpoint 机制的核心价值在于**容错**与**断点续训**。

### 容错性

当训练意外中断时，可以从最近的存档点恢复，而不是从第 0 步重头开始。

### 恢复优化器状态（最易忽略的关键点）

像 AdamW 这样有状态的优化器，内部记录了每个参数的动量 $m$ 和平方梯度 $v$。如果只恢复模型权重而不恢复优化器状态，训练会产生巨大的数值冲击，导致 Loss 剧烈震荡甚至爆炸。

> [!WARNING]
> **常见误区**：仅保存 `model.state_dict()` 而忽略 `optimizer.state_dict()`，会导致恢复后训练曲线出现异常跳变，前期收敛成果几乎白费。

### 断点续训与学习率调度

通过记录 `iteration`（迭代步数），可以确保学习率调度器（Scheduler）从正确的时间点继续执行余弦退火等策略，避免学习率跳变。

---

## state_dict 机制

在 PyTorch 中，无论是模型（`nn.Module`）还是优化器（`Optimizer`），其核心状态都存储在 `state_dict` 中。它是一个标准的 Python 字典。

| 对象 | 字典内容 | 示例键 |
|------|----------|--------|
| 模型 | 每一层的名称映射到对应的参数张量 | `layers.0.attn.q_proj.weight` |
| 优化器 | 当前所有参数的动量信息和步数 | 内部状态键（如 `exp_avg`、`exp_avg_sq`） |

## 代码实现

### 保存 Checkpoint

将所有状态"打包"成一个单一的字典，然后利用 `torch.save` 进行序列化。

```python
def save_checkpoint(
    model: torch.nn.Module, 
    optimizer: torch.optim.Optimizer, 
    iteration: int, 
    out: typing.Union[str, os.PathLike, typing.BinaryIO, typing.IO[bytes]]
):
    """
    保存当前训练状态。
    """
    # 1. 构建一个包含所有必要信息的字典
    checkpoint = {
        'model_state_dict': model.state_dict(),
        'optimizer_state_dict': optimizer.state_dict(),
        'iteration': iteration
    }
    
    # 2. 使用 torch.save 将字典写入目标（可以是路径或文件流）
    torch.save(checkpoint, out)
```

### 加载 Checkpoint

加载过程是保存的逆运算。需要注意的是，`iteration` 在这里是一个返回值。

```python
def load_checkpoint(
    src: typing.Union[str, os.PathLike, typing.BinaryIO, typing.IO[bytes]], 
    model: torch.nn.Module, 
    optimizer: torch.optim.Optimizer
) -> int:
    """
    从检查点恢复状态，并返回保存时的迭代次数。
    """
    # 1. 加载字典
    # 使用 map_location='cpu' 可以防止在没有 GPU 的机器上加载时报错
    checkpoint = torch.load(src, map_location='cpu')
    
    # 2. 恢复模型权重
    model.load_state_dict(checkpoint['model_state_dict'])
    
    # 3. 恢复优化器状态（动量、步数等）
    optimizer.load_state_dict(checkpoint['optimizer_state_dict'])
    
    # 4. 返回保存时的迭代次数
    return checkpoint['iteration']
```

> [!TIP]
> **实现细节**：`torch.load(..., map_location='cpu')` 确保在无 GPU 环境下也能正常加载，避免设备不匹配报错。

## 操作案例

假设在训练过程中，每 1000 步保存一次。

### 场景 A：正常训练并存档

```python
# 训练到第 1000 步
save_checkpoint(model, optimizer, 1000, "checkpoint_1000.pt")
```

### 场景 B：程序意外崩溃后重启

```python
# 重启脚本
model = TransformerLM(...)
optimizer = AdamW(model.parameters(), ...)

if os.path.exists("checkpoint_1000.pt"):
    # 读档
    last_step = load_checkpoint("checkpoint_1000.pt", model, optimizer)
    print(f"成功恢复，从第 {last_step + 1} 步继续训练")
```

> [!NOTE]
> 恢复后应从 `last_step + 1` 开始继续训练，而非从 `last_step` 开始，避免重复执行同一步。\n
