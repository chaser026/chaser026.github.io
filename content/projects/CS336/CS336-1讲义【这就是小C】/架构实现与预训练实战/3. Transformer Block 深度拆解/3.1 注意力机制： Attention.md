# 3.1 注意力机制：Attention

> [!NOTE]
> **本节目标**
> - 理解 Attention 机制的核心作用与计算逻辑
> - 掌握缩放因子 $\sqrt{d_k}$ 的意义：从方差影响 → Softmax 求导（梯度趋零）→ 模型参数更新停滞的完整链路
> - 能够独立实现 Scaled Dot-Product Attention 的代码

---

#### 核心思想

Attention 的本质是：**模型应根据当前需求，从上下文中按比例提取重要信息、忽略不重要信息，从而生成新的特征表示。**

> [!TIP]
> 可以将 Attention 理解为一种"语义对齐"机制——它让每个 Token 动态地决定自己应该从序列中的哪些位置"借"信息。

---

#### 具象化理解：以"苹果"为例

假设输入序列为 `["我", "吃", "苹果"]`，我们观察 Token "苹果" 如何通过 Attention 确定自身语义是"水果"而非"手机"。

| 组件 | 符号 | 物理含义 | 形象化描述 |
|------|------|----------|-----------|
| 查询 (Query) | $Q$ | "我需要什么？" | "苹果"发出询问："周围有没有关于动作或属性的词，能帮我确定身份？" |
| 键 (Key) | $K$ | "我有什么标签？" | "吃"的标签是"动作：进食"；"苹果"的标签是"物体：水果/电子产品" |
| 值 (Value) | $V$ | "我包含什么信息？" | "吃"提供"[含有吞咽、食物属性]"；"苹果"提供"[圆形、多汁、脆]" |

**计算逻辑三步走**：

1. **匹配**（$QK^\top$）："苹果"的 $Q$ 与"吃"的 $K$ 匹配度高（动宾关系），同时与自身 $K$ 匹配度也很高。
2. **分配权重**（Softmax）：模型给"自身"分配 60% 权重，给"吃"分配 30% 权重，其余 10% 分给其他词。
3. **融合**（加权求和）：输出向量 $= \sum_i \text{weight}_i \cdot V_i$。

> [!NOTE]
> 更新后的"苹果"向量携带了"吃"的特征，使后续层能够明确此处指的是一种"食物"。

---

#### 核心公式

Scaled Dot-Product Attention 的完整计算公式为：

$$\text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$

其中：
- $Q \in \mathbb{R}^{n \times d_k}$：查询矩阵，$n$ 为查询序列长度
- $K \in \mathbb{R}^{m \times d_k}$：键矩阵，$m$ 为键值序列长度
- $V \in \mathbb{R}^{m \times d_v}$：值矩阵
- $d_k$：键/查询向量的维度
- $\sqrt{d_k}$：缩放因子

---

#### 数值推演：掩码与权重变化

假设序列长度 $S=3$，特征维度 $d_k=2$。

**Step 1：计算原始分数（Scores）**

计算 $QK^\top$ 得到 $3 \times 3$ 矩阵。注意：对角线（自己看自己）通常分值最高。

**Step 2：因果掩码（Causal Masking）**

在 GPT 等 Decoder 架构中，为防止训练时"偷看"后文，将上三角（未来信息）设为 $-\infty$。

> [!IMPORTANT]
> 物理意义：单词"吃"只能看到"我"和"吃"，看不到后面的"苹果"。这是自回归生成的关键约束。

**Step 3：归一化（Softmax）**

对每一行进行 Softmax，使每行总和等于 1。

> [!TIP]
> 观察结果：最后一行"苹果"对自身关注度最高（约 0.88），同时从"吃"吸收了约 0.12 的能量。

---

#### 缩放因子 $\sqrt{d_k}$ 的意义

公式中除以 $\sqrt{d_k}$ 是为了解决**梯度消失**问题。完整的影响链路如下：

1. **方差影响**：随着维度 $d_k$ 增大，点积 $QK^\top$ 的方差随之增大，导致 Scores 中出现极大数值（如 100）。
2. **Softmax 求导影响**：Softmax 函数在输入值很大时进入饱和区，其导数（梯度）趋近于 0。
3. **模型参数影响**：梯度趋零 → 参数更新停止 → 模型无法学习。
4. **解决方案**：除以 $\sqrt{d_k}$ 将分数分布拉回 0 附近，确保信号既不过载也不消失，使梯度下降能够正常进行。

> [!WARNING]
> 如果省略缩放因子，在高维场景下模型训练将几乎停滞——这是实现 Attention 时最常见的误区之一。

---

#### 代码实现

```python
import torch
import math
from .nn import softmax  # 使用此前实现的数值稳定版 Softmax

def scaled_dot_product_attention(
    Q: torch.Tensor,
    K: torch.Tensor,
    V: torch.Tensor,
    mask: torch.Tensor = None
) -> torch.Tensor:
    """
    参数:
        Q: [..., n, d_k] (n 为查询序列长度)
        K: [..., m, d_k] (m 为键值序列长度)
        V: [..., m, d_v]
        mask: [n, m] 布尔矩阵, True 为保留, False 为屏蔽
    """
    d_k = Q.size(-1)

    # 1. 计算相似度分数 (Scores)
    # einsum 语义: 沿着 d_k 维度(k)进行点积, 保留 batch(...)、query(n) 和 key(m) 维度
    # 结果形状: [..., n, m]
    scores = torch.einsum('...nk, ...mk -> ...nm', Q, K) / math.sqrt(d_k)

    # 2. 应用因果掩码 (Masking)
    if mask is not None:
        # 将 False 对应位置的分数设为负无穷，使其在 Softmax 后概率为 0
        scores = scores.masked_fill(mask == False, float('-inf'))

    # 3. 计算注意力权重 (归一化)
    # dim=-1 对应的是每一个 Query 对所有 Key 的分布
    probs = softmax(scores, dim=-1)

    # 4. 加权求和得到输出 (Output)
    # einsum 语义: 利用 probs(n, m) 对 V(m, k) 进行加权求和
    # 结果形状: [..., n, d_v]
    output = torch.einsum('...nm, ...mk -> ...nk', probs, V)

    return output
